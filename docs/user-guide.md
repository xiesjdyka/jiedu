# 界渡使用指南

界渡把 AI 对话、附件和本地资料留在你的知识工作区，让你能找到出处、整理有用结论，再交给所选模型继续使用。

适合经常换对话或模型、长期推进项目、已经积累很多资料的个人用户。如果你只需要临时问答，现有聊天工具通常就够用；界渡的价值要体现在下次还能找到并接着用。

## 先完成一件小事

第一次打开会先显示可复制的本机连接提示词；复制后才能确认进入。复制只是交付操作说明，后续仍需查看安装、工作区、来源读取、归档和索引的真实状态。然后连接或创建工作区，导入一份普通文本或截图，搜索其中一句话并打开出处。

当前主要核验 Codex 与 Hermes 的本机来源。Codex 可读取本机 JSONL 和符合结构的 SQLite 会话历史；来源身份不明的记录会留待复核，不会被当成已归档的用户对话。其他智能体能否读取知识、能否归档历史和能否持续采集是不同能力，请以对应连接页的实际状态为准。

## 1. 保存并找回资料

1. 在「工作区」选择保存位置，按预览初始化，或连接已有界渡工作区。
2. 进入「知识 → 导入资料」，选择来源并检查预览，再开始保存。
3. 查看每个文件的结果：保存原件、生成可读文字和识别失败分别表示不同结果。
4. 搜索时选择资料所在范围：新导入且待确认的内容通常在「收件箱」；原始聊天和附件在「原始证据」；确认后的项目页和知识页在「正式知识」；工作区根目录及普通文件夹内的 Markdown 在「本机资料」，可独立建立语义索引。
5. 从命中项打开来源核对正文；只有保存了文件，并不保证文字已经可搜索。

## 2. 图片和扫描 PDF 为什么需要文字识别

识别让截图中的一句话也能被搜索到，并能作为模型回答的资料。它保留原件，另外生成可阅读文字，不改变图片。此节描述的是资料导入和文字检索；管家直接发送原图给支持图片的外部模型是另一条通路，不会自动 OCR 或把原图写入知识。

普通导入成功后，可读文字保存在「99_收件箱/导入/来源文件夹/_派生知识」，原图保留在同一导入目录。先在「收件箱」范围搜索图片中的特征词；也可在管家选择「待确认资料（收件箱）」。外部模型读取收件箱还需在外发设置单独允许，选择范围不会自动授予外发权限。打开来源，同时核对原图或 PDF 页。数字、日期和表格尤其需要核对；识别结果仍标记为待核对，不会自动成为正式知识。

若只保存了原件，检查结果里的原因。缺少 OCR 组件、文件损坏、超出处理限制和没有识别到文字应分别处理。1.1.4 Windows 安装器会自动下载并校验 OCR 组件；若下载或校验失败，应重新运行安装器。源码安装仍不自带 OCR 运行环境和模型文件。

## 3. 让换来的模型知道怎样使用界渡

在「管家」选择已有本机模型，或配置外部服务及型号。先核对模型连接，再决定本轮要查哪类资料、是否启用已授权工具。

管家负责向模型提供界渡的用途和操作入口；模型通过实际工具取得资料与状态。工具关闭时只能回答和说明操作，不能宣称已经写入。工具执行受你设置的范围约束，完成与否以实际结果为准。

可以先问「这里能帮我做什么？」；再选一份合成资料，问「找出这份资料提到的下一步，给我出处」。看到回答后打开来源核对，确认它确实用了这份资料。

外部 API 会发送本轮问题与获准内容，也可使用当前接入配置下、本对话中最近最多 8 对已完成问答及其可核验原图。超过容量时整对省略较早内容并提示；旧图缺失、变化或不再符合限制时，不会伪造图片，会提示重新选择。旧本地对话、其他接入配置、工作区或工具派生历史、全库和画像不自动外发。本轮读取资料仍受当前外发授权约束；切换模型不代表它自动了解全部旧聊天。

### 思考与生成长度

可切换思考的模型在未保存偏好时默认开启，已有关闭选择会保留。不支持或未验证的能力保持关闭；必须思考的模型不能关闭。外部模式选择“自动”时，思考开启/关闭的生成目标分别为 8192/4096 词元；思考和回答共用额度，实际仍受服务输出上限和上下文空间限制。明确选择的数字或“最大”保留；只有思考而未形成回答、或回答达到额度上限时，界面会按实际结果提示。

点击“新对话”后可以继续输入。创建期间暂不能发送或更改图片，完成后新输入会带入该对话；切换会话或工作区后，旧请求不会覆盖当前输入。

### 图片与未发送草稿

使用附件按钮、拖拽或粘贴添加 PNG、JPEG、GIF、WebP 原图，先查看缩略图，再发送。仅已确认支持图片的外部模型可用；本机模型和 Hermes 通路不支持图片，不会静默改用 OCR 文本。只有图片时，管家会描述图片内容。应用上限为每张 8 MiB、每轮 4 张且合计 16 MiB，这不是服务商 API 的上限说明。

每会话未发送草稿同为 4 张/16 MiB，刷新或重新打开后可恢复预览、移除和继续发送。24 小时规则仅清理未绑定的草稿原件，已发送原图不受此规则影响；状态不明的旧原件会保留并计入容量，不自动加入发送列表。发送期间不能改动附件。上传失败且本机文件仍在时可重试；没有可重传文件时应重新选择原图。原图发送不自动 OCR、入知识或形成正式知识页。

### 本机 Hermes 问答

在模型设置选择“本机 Hermes”，可复用该软件已有的模型配置，无需重复输入密钥。它发送当前问题、公开产品说明和当前界渡对话的有限已完成问答，不读取旧 Hermes 会话，不执行界渡工具或私有知识检索；思考与输出额度由 Hermes 管理。此前实测限 DeepSeek，其他供应商或 Hermes 版本以对应回执为准。此问答通路与 Hermes 来源归档、MCP 配对分别管理。

## 4. 从聊天变成可复用知识

「对话档案」保存来源记录；「整理中心」处理值得保留的结论。用户可见的发言、commentary 进度和正文代码例可以作为原档案保存，保存它们不等于形成正式知识。整理应依据来源提炼可核实事实、已作决定和必要约束，保留出处；查看建议的正文、来源、保存位置和差异，核对后再保存。归档、建议生成和正式保存是三个阶段。

内部 analysis、工具原始结果、用量与协议记录不应混作普通聊天；来源适配应按记录结构区分。正文里真实出现“analysis”“tool”等词，或用这些词举代码例，不能仅凭关键词删除。各来源的过滤和恢复结果以该候选回执为准，取不到的原件与已保存正文应分别说明。

逐消息整理会检查消息的入口、复核、交付与精确证据资格；原始证据展示仍可单独保留提示/工具记录。整份 conversation.md 读取与 Wiki 尚未逐条投影，不能把这一边界理解为所有入口已经过滤完毕。来源游标、旧历史和账本不因过滤规则重置。

旧建议过期后，会显示“等待下次整理更新”。已连接 AI 实际发起知识 Wiki 整理并领取任务时，会自动接续每条待更新建议，重新读取它的来源和目标。“已领取”表示任务已交给 AI，不保证它此刻仍在执行。产生可核实的新建议后，旧建议保留为历史，新建议仍需你审核；若现有目标已经包含结果，也需核验当前读取和正文一致性。来源缺失、权限不足或没有产出结果时仍显示需处理，不会假装完成，也不会自动批准正式写入。

这条自动衔接适用于已连接整理 AI 通过 Wiki/MCP 领取任务的通路，沿用原有接口，无需新增工具参数。管家内部独立领取工具与独立手动提炼包不在本次自动衔接范围；手动提炼包和更新指令导出保留为高级备用，复制或导出不会启动任务。保存后查看知识页和版本记录；撤销会检查目标是否又被修改，不应该覆盖后来的人工修改。

## 常见疑问

- 搜不到刚导入的内容：先检查是否生成可读文字，再核对搜索范围和索引状态。
- 管家说不能操作：检查本轮工具开关、已授权范围和这项功能是否有管家工具；有些功能需要在对应页面完成。
- 下载完模型却不能用：下载、选中型号和推理组件就绪是三个步骤；大模型还需要足够的硬件资源。
- 接入模型就一定能联网吗：模型 API、服务商自带搜索和界渡网页/搜索工具是不同入口，以所选服务及启用状态为准。
- 附件显示缺失：先看对应引用和原因；失效交付链接不能直接算成用户上传文件丢失。
- 归档提示“进度需要恢复”：这不是手动暂停。保留工作区和来源记录，不要重新初始化或删掉进度文件；按[归档进度保护](archive-recovery.md)核验后恢复。
- 归档显示“正在核对并补齐历史聊天”：正在检查旧格式并追加漏存的公开正文；无需重新导入。用量统计和内部通信单独识别，不会塞进聊天。“历史聊天正文已核对”与“附件已取得”分别判断；未识别内容仍会明确列出。

## 5. 查看版本与更新

当前程序、桌面外壳和在线安装器候选均为 `1.1.7`，运行资源沿用已固定来源与哈希。关于、托盘和窗口使用既定界渡图标。安装包的实际安装、运行与资料保全，以对应 SHA256 的随附回执为准。

程序启动后和持续运行期间会低频检查更新，正常间隔约 12 小时，失败会退避重试；不会自动下载安装。发现新版会显示提醒，可选择稍后或“更新并重启”，设置和托盘也保留手动检查入口。公开渠道尚未发布、不可访问或签名清单过期时，会说明原因，不会把检查失败说成已是最新版。

用户确认后，程序校验发布签名、版本、摘要和下载地址，等待当前任务自然结束再更新。小更新可以替换程序文件；Python、依赖或原生外壳变化则通过同一入口使用完整安装器。完整升级仅适用于安装目录与工作区分离、安装归属可核验的新安装版。旧自包含工作区会安全提示单独安装新版并连接原工作区，不会替换整个资料目录。程序目录内发现未登记文件会暂停升级，避免静默丢失自定义资料。

完整升级保留工作区连接、模型配置、进度、可选运行组件和最近一次完整回退副本；新版本健康检查失败时尝试恢复，仍被进程占用或归属不明时保留恢复材料并明确提示，不强制杀进程。更早成功回退副本只有在精确清单仍一致时才清理，因此后来放入的文件不会被当成旧缓存删除。

正式更新地址为 GitHub 项目 `xiesjdyka/jiedu` 的最新 Release；候选审阅期间仓库及发布内容可能仍为私有，公开可用性以正式发布为准。Windows Authenticode 签名尚未办理，安装器可能显示“未知发布者”；更新清单签名与 Windows 发布者签名是两套不同机制。
