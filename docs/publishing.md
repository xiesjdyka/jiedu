# 首次发布清单

当前源码候选不会自动上传、创建仓库或发布 Release。维护者应使用单独的新仓库导入审查过的源码，不能直接推送个人开发仓库的 Git 历史。

1. 运行 scripts/setup.ps1，检查依赖安装与 pip check，完成隔离的首次启动、导入、检索和重启验收。
2. 核对 public-source-files.txt 中每个文件。新增源码需要明确加入；脚本不会自动把目录里的新文件一起打包。检查内容中的隐私与凭据，文件白名单不能代替内容审查。
3. 执行 `python scripts/export_source.py --output ../jiedu-source-1.1.0-rc.1.zip`。输出必须是新文件名。压缩包包含逐件 SHA-256 清单。
4. 在最终压缩包上再次做隐私检查；不要公开验收目录、临时副本、历史包、模型、环境或工作区。保留私有审查回执。
5. 新建公开仓库后，在 Settings → Code security 中启用 Private vulnerability reporting，并从另一登录态确认 Security → Report a vulnerability 入口可用。开启 Secret scanning / Push protection（若仓库设置中可用）。未启用前 SECURITY.md 必须保留未配置说明。
6. 推入清洁源码后等待 Windows source checks 的安装和桌面构建两项检查完成。工作流文件存在不等于云端检查已通过。不要给拉取请求提供生产凭据或数据。
7. 使用干净 Windows 测试环境验证安装和桌面操作。源代码体验版可以明确标记未覆盖项；面向普通用户的完整软件包必须另行通过运行时、窗口、托盘、升级和卸载保全验收。
8. 核对 VERSION、Python 和桌面版本，使用 `v1.1.0-rc.1` 作为候选 tag。准备发布说明，列出已验证能力、未验证项与可选下载占用；发布按钮由维护者最终触发。
