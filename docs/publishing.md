# 1.1.10 候选发布清单

当前 1.1.10 源码候选不会自动上传或发布 Release。公开仓库已有历史版本；本候选仍须独立审查源码、构建产物、更新清单和安装升级结果，不能把本地验证写成已发布验收。

1. 运行 scripts/setup.ps1，检查依赖安装与 pip check，完成隔离的首次启动、导入、检索和重启验收。
2. 核对 public-source-files.txt 中每个文件。新增源码需要明确加入；脚本不会自动把目录里的新文件一起打包。检查内容中的隐私与凭据，文件白名单不能代替内容审查。
3. 执行 `python scripts/export_source.py --output ../jiedu-source-1.1.10.zip`。输出必须是新文件名。压缩包包含逐件 SHA-256 清单。
4. 在最终压缩包上再次做隐私检查；不要公开验收目录、临时副本、历史包、模型、环境或工作区。保留私有审查回执。
5. 核对公开仓库的安全报告入口和 Secret scanning / Push protection（若仓库设置中可用），并从另一登录态确认实际可用。配置未核实前，SECURITY.md 不应宣称已启用。
6. 推入清洁源码后等待 Windows source checks 的安装和桌面构建两项检查完成。工作流文件存在不等于云端检查已通过。不要给拉取请求提供生产凭据或数据。
7. 使用干净 Windows 测试环境验证安装和桌面操作。源代码体验版可以明确标记未覆盖项；面向普通用户的完整软件包必须另行通过运行时、窗口、托盘、升级和卸载保全验收。
8. 运行 `python desktop/release_version.py check`，核对 `1.1.10` 的 Python、Cargo、Tauri 和安装器版本字段。只有产物及更新清单完成独立验收后，才准备 1.1.10 tag 和发布说明；列出已验证能力、未验证项与下载占用，发布按钮由维护者最终触发。

旧版升级必须保留工作区资料、身份权限、采集范围及同步进度。`jiedu-self-contained-v1` 或归属不明的布局不得整体覆盖；需单独安装新版程序再连接原工作区。整理建议不会自动写入正式知识，仍由用户核对确认。
