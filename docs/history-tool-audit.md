# 历史工具执行载荷只读核查

适用于需要核对旧归档是否混入工具执行卡、调用载荷或工具输出的用户。核查不执行消息中的命令，也不会自动删除或隐藏消息。

## 运行

使用安装包自带的 Python，或 Python 3.12 及以上版本。以下路径是示例，换成自己的安装位置和知识工作区：

```powershell
& 'D:\Apps\界渡\.jiedu\runtime\python\python.exe' -B 'D:\Apps\界渡\.jiedu\program\scripts\audit_tool_payload_history.py' --workspace 'D:\我的知识库' --output 'D:\审计报告\tool-history.json'
```

也可把明确指定的报告放在该工作区的 `.jiedu/artifacts` 或 `.jiedu/audit`。工具拒绝覆盖输入文件、同步状态、原始账本或知识正文，拒绝目录链接与路径逃逸。已有输出只有同一报告格式才可更新；输入在核查中变化会明确失败，应稍后重试。不会自动停止正在运行的界渡。

## 判定范围

- 读取原始消息账本、归档登记和身份别名，以及已登记的标准消息 JSONL。
- 明确工具角色、工具载荷类型或已知工具路由仅列为 `needs_review`，需结合原始来源复核，不能直接当作删除清单。
- 可见思考、分析说明、普通进度、解释、代码示例、用户粘贴代码保留。正文同时带有 `tool_calls` 不会让整条 assistant 消息成为工具输出。
- 不按 ADB、echo、运行命令、`<think>` 或代码围栏等正文词句判断。未知 `display_kind`、缺结构字段、旧 Hermes 补档、ChatGPT Web 或豆包历史都不能凭名称或缺标记认定为工具日志。
- 旧账本与标准迁移账本中的相同来源消息是不同物理投影；工具分开报告物理行与别名等价行，不把它们累计为重复聊天。

## 输出与限制

报告只包含稳定身份、哈希、允许的结构事实、覆盖范围与缺口，不保存正文、标题、引用片段或凭据。相同输入生成相同的核查指纹。

报告中的 `source_binding_checked=false` 表示工具没有读取 Codex rollout、Hermes 数据库或历史批准计划。需要按稳定会话/消息身份、来源版本和正文哈希进一步绑定；缺来源或版本冲突的记录保持不变。历史恢复中已审核的非 active 记录、已脱敏正文也不能因此撤销。

`proposed_changes=[]`、`production_changes=0` 是该工具的固定合同。零结构命中只说明本次覆盖范围中没有待复核工具标记，不代表所有历史来源都已完成验证。核查不会修改原始证据、消息 ID、游标、附件、候选或正式知识，不会重新归档。若来源核实确有误收，应先审阅其稳定身份、可逆映射、聊天/搜索/整理投影及旧引用影响，再单独执行受控修复；不能静默删除正式知识。
