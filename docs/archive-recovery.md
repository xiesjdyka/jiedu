# 归档进度保护与恢复

## 用户看到异常时

“归档进度需要恢复”和“已暂停”含义不同。前者表示关键状态无法读取，程序停止采集以保护已有记录；不能用重新初始化、删除进度文件或重新导入来处理。

现有聊天正文及附件与同步状态分别保存。状态损坏不等于正文丢失，但必须实际核对，不能仅凭页面显示判断。恢复期间保留完整工作区和来源客户端的本地记录。

## 当前保护措施

- Codex 归档进度、来源身份、会话目录表以及会话元数据使用刷盘后原子替换，并保存一份有效旧版本。`.last-good` 是恢复依据，可能落后于原件，不能直接自动覆盖当前进度。
- 损坏的进度和目录表会阻止重新配置或归档写入，不会按空工作区处理。来源身份无法读取时禁止创建替代身份，避免同一会话重复建档。
- 恢复时同时核对来源会话编号、物理文件身份、读取边界指纹、会话消息编号及附件原件；原件和故障文件先保全。
- 运行日志记录本轮增量，不反复复制整个归档快照。普通日志约 8 MiB 轮换，保留一份前段；已存在的超大历史日志单独保留，需核实用途后才能清理。

这些措施降低状态写入中断的影响，不能替代工作区备份，也不能保证抵御磁盘或系统层面的损坏。

## 维护者恢复顺序

1. 停止所属采集服务，复制故障字节；记录原始正文与附件哈希、消息编号以及目录映射。
2. 找到可信完整备份，结合最后有效审计和每个会话的元数据恢复策略及进度。保留原来源实例 ID、排除范围和会话 ID。
3. 用来源文件身份、边界与指纹验证每个进度；无法验证时停在该来源，不假定从零重跑安全。历史批次与后续增量分别恢复。
4. 在独立合成工作区测试损坏阻断、重启、增量和重复同步；恢复正式状态后有界补采。
5. 对照旧记录检查原件保留、消息编号唯一、游标连续，再检查真实页面和重启后的新增同步。记录未取得附件或未知格式等既有缺口。

正式恢复不得更改模型配置、凭据或授权范围；不以恢复成功推断所有历史附件已齐全。

## 旧格式补档与完成状态

旧版 Codex 桌面记录可能没有回答阶段标记。采集器只接纳已核实的旧版公开助手正文结构；未知阶段、内部代理通信、工具调用、用量统计和语音会话开始/结束记录不会被当作用户聊天。无法确认的结构仍单独保留，不能仅按名称批量清空。

界面中实际向用户发出的异步问题卡片也属于公开对话：按卡片的调用编号保存问题及选项，不把整段工具参数或工具返回塞进正文。普通界面消息镜像不重复存储；占位文本不当成回答。桌面升级补入顺序号后，旧事件可在移除该新增字段的序列化结果与旧指纹精确一致时重新关联，回执同时保留旧、新指纹及关联方法。

升级后的格式核对使用独立进度，从原始来源逐条对照已存消息。缺少的公开正文按原会话和消息编号追加，并在阅读视图中恢复原顺序；原同步游标不回退。已存编号对应不同正文时停止该来源，不覆盖原记录。原待核对台账不删除，已核清的项目另存来源指纹与分类依据。

维护者增加格式规则时应升级格式策略版本，让已检查来源重新通过独立核对；不能回退正常历史或增量游标来触发补档。旧版核对记录和累计补回数量仍保留。

页面分别显示：

- **正在核对并补齐历史聊天**：文件还在逐条核对，百分比只说明本批处理进度。
- **历史聊天正文已核对**：本批获准来源在捕获边界内的正文核对完成；后来新增的内容继续自动同步。
- **尚未识别的内容**：尚未确认其含义或无法定位的记录，不能算作完整归档。
- **文件引用未取得原件**：对应路径或链接的文件尚未取得；引用所在正文可能已经完整保存。原文件不会用一个同名新文件冒充。

暂停归档也暂停后台格式补档。进度保存在工作区，重启后续接。维护者验收应额外全量对照固定来源范围的消息身份、正文、角色和时间，并检查旧账本前缀及原附件哈希；仅看到“读取100%”或单次新增为0不能证明聊天完整。


## 历史交付文件的证据恢复

历史文件引用按“来源会话、消息编号、原引用”逐项核对，不按文件名匹配补齐。迁移清单中的原路径与 SHA-256、原回复公布的 SHA-256、原消息明确绑定的图片，以及可追溯的原文件复制记录可作为恢复依据；还必须考虑引用时间，后改的同路径文件不能冒充旧版本。

维护接口 `attachment_reference_review.apply_review` 在写入前核对整个清单的来源身份、消息指纹和候选文件 SHA-256。补回仅追加附件记录及核对回执，并重建阅读视图；不改原消息、不回退同步进度。重复执行保持原引用身份。已保存且校验完整的附件不因旧路径消失或出现同名新文件而被覆盖；原件校验失败时明确报错。

核对后仍无法确认的引用保留具体原因，后台不能仅凭原路径重新出现就替换它。后来取得充分证据时可再次提交经过哈希核验的恢复记录。工具返回的历史图片副本必须单独说明，不能保证其编码与原磁盘文件相同。页面分别显示核对数量、补回数量、图片副本数量，以及仍缺少内容的完整路径和逐项原因；核对回执保存在工作区审计目录。
